Kullanıcı El Kitabı

DORA Ajan Paketi · Sürüm 1.26.0 · Bu kitap iki bölümden oluşur: Kullanıcı ve Yönetici.

Bölüm 1 — Kullanıcı

1.1 İlk giriş

  1. Tarayıcıda https://<sunucu>/app/ adresini açın.
  2. Kullanıcı adı ve parolanızı girin.
  3. Yönetici size davet e-postası gönderdiyse bağlantıya tıklayıp parolanızı belirleyin

(bağlantı 30 dakika geçerlidir, tek kullanımlıktır).

  1. İlk girişten sonra Güvenlik → Kurulumu başlat ile iki adımlı doğrulamayı açın.
Parolanızı unuttuysanız yöneticinizden sıfırlama bağlantısı isteyin. E-postanıza gelmişse bağlantıyı açıp yeni parolanızı belirleyin.

1.2 İki adımlı doğrulama (2FA)

AdımNe yapılır
1Güvenlik sayfasında Kurulumu başlat
2Telefonunuzda Google/Microsoft Authenticator → Kurulum anahtarını gir
3Ekrandaki anahtarı 4'lü gruplar halinde yazın
4Uygulamanın verdiği 6 haneli kodu girin → Etkinleştir
510 kurtarma kodunu kaydedin (bir daha gösterilmez)

Sonraki girişlerde paroladan sonra 6 haneli kod istenir. Kod gelmezse kurtarma kodlarından birini kullanın — her kod tek kullanım.

1.3 Durum sayfası

Girişte gördüğünüz Durum sayfası üç şeyi gösterir:

  • Kaç adım tamamlandı (6 adım)
  • Kurum büyüklüğü ve denetleyici kurum
  • Kaç sistem bağlı (olay, destek, uyum, envanter)

1.4 Kurum bilgileri

Kurum bilgileri sayfasında kurum adı, büyüklük (tier), denetleyici kurum, faaliyet ülkesi ve faaliyet alanları girilir. Bu bilgiler raporlarda ve kanıt paketinde kullanılır.

1.5 Kurulum adımları

AdımNe girilir
1Hizmetleriniz — kritik hizmetler, sahipleri, kritiklik
2Kesinti toleransları — her hizmet için MTD / RTO / RPO (saat)
3Varlıklarım — sunucu/sistem listesi (CSV yükleme veya yapıştırma) + Sorumlular
4Senaryo testleri — üç senaryo için doğruluk, SLA ihlali, hash zinciri
5Öz değerlendirme — 28 DORA maddesi için kapsama ve bağımsız doğrulayan
6Canlıya geçiş — ajan otonomi seviyeleri, gölge/yarı-otomatik gün sayısı

Her adımda "adımı denetle" düğmesi vardır: eksik varsa kırmızı çarpı ile listeler.

1.6 Envanter yükleme (CSV)

  1. Varlıklarım → Şablon indir
  2. Excel'de doldurun: id, ad, kritiklik, tedarikçi
  3. Dosyayı seçin → otomatik yüklenir

Kritiklik: kritik, önemli, standart (İngilizceleri de kabul edilir).

1.7 Olay kaydı ve raporlama süreleri

SIEM bağlıysa olaylar otomatik gelir; gelmiyorsa yönetici SIEM olayları → Olayları çek der.

  1. Olay kayıtları tablosunda olay satırını görün.
  2. Müşteri sayısı, kesinti dakikası, ekonomik etki alanlarını doldurun.
  3. kaydet → aktif yap (dört göz açıksa ikinci yöneticinin onayına gider).
  4. Raporlama süreleri kartında üç sayaç görünür:
AdımSüreRenk
İlk bildirim4 saatyeşil = gönderildi, turuncu = yaklaşıyor, kırmızı = gecikti
Ara rapor72 saataynı
Nihai rapor1 ayaynı
  1. Raporu dışarıda gönderdikten sonra "… gönderildi" düğmesine basın; referans numarası

girebilirsiniz.

1.8 Olay geçmişi

Olay satırında geçmiş düğmesi: kim, ne zaman, ne yaptı (oluşturma, güncelleme, raporlama, onay).

1.9 Belgeler ve kanıt paketi

  • Belgeler sayfası oturumda üretilen kayıtları listeler.
  • Kanıt paketi oluştur → tüm kayıtlar tek zip'te, imzalı.
  • Yönetim raporu (PDF) → kurum, fazlar, olaylar, süreler, onaylar, kapsama özeti.

1.10 Ara

Ara sayfası süreç, kontrol, ajan, terim ve DORA maddelerinde arama yapar. Türkçe karakter duyarsızdır (siniflandirma = sınıflandırma).

1.11 Parola değiştirme

Parolamı değiştir → mevcut parola + yeni parola (en az 8 karakter). Değişince diğer cihazlardaki oturumlar kapanır.

2.2 E-posta (SMTP)

Yönetim → E-posta (SMTP): sunucu, port, gönderen, kullanıcı, parola, SSL seçenekleri. Test gönder ile doğrulayın. Gönderilemeyen iletiler kuyruğa düşer; Kuyruğu gönder ile tekrar denenir.

2.3 Bildirimler

Yönetim → Bildirimler: etkin, alıcılar (virgülle). Açıkken:

  • Raporlama süresi yaklaşan/geçen olaylar
  • Bekleyen onay talepleri

için e-posta gider. Şimdi tara ile elle denersiniz. Aynı uyarı ikinci kez gönderilmez.

2.4 Dört göz onayı

Yönetim → Onay akışı → Etkin. Açıkken olay sınıflandırması ve canlıya geçiş ikinci yöneticinin onayına gider; talep eden kendi talebini onaylayamaz.

Tek yönetici varsa açmayın — talep onaylanamaz. Önce ikinci bir yönetici oluşturun.

2.5 Entegrasyonlar

Entegrasyonlar: SIEM / ITSM / GRC / CMDB için ürün, adres, kimlik doğrulama, anahtar. Bağlantıyı dene erişimi sınar; SIEM olayları sayfasında olayları çekersiniz.

2.6 SIEM olay kuralları ve zamanlanmış çekme

  • Olay kuralları: hangi anahtar kelimelerin kayıt açacağı, veri kaybı/yetkisiz erişim işaretleri.
  • Zamanlanmış çekme: etkin + aralık (dakika) → sunucu kendisi çeker, taslak kayıt üretir.

2.7 SSO (kurumsal giriş)

Yönetim → Kurumsal giriş (SSO / OIDC): issuer, client ID, redirect URI, secret. Ayrıntı: docs/SSO-KURULUM.md. TLS olmadan çalışmaz.

2.8 Yedekleme

Ayrıntı: docs/YEDEKLEME.md.

2.9 Denetim kaydı

Yönetim → İşlem kaydı son 150 işlemi gösterir; CSV indir ile tamamı alınır.

2.10 Teknik panel

Sol menüde Teknik panel → statik rapor panosu (süreçler, kontroller, ajanlar, sözlük, DORA eşlemesi). Canlı pano ise anlık veriyi gösterir.

User Handbook

DORA Agent Package · Version 1.29.0 · This handbook has two parts: User and Administrator.

Part 1 — User

1.1 First sign-in

  1. Open https://<server>/app/ in your browser.
  2. Enter your username and password.
  3. If an administrator sent you an invitation e-mail, click the link and set your password

(the link is valid for 30 minutes and can be used once).

  1. After signing in, open Security → Start setup to enable two-factor authentication.
If you forget your password, ask your administrator for a reset link. If it arrives by e-mail, open the link and set a new password.

1.2 Two-factor authentication (2FA)

StepWhat to do
1On the Security page press Start setup
2In Google/Microsoft Authenticator choose Enter a setup key
3Type the key shown on screen in groups of four
4Enter the 6-digit code from the app → Enable
5Save the 10 recovery codes (shown only once)

On later sign-ins you enter the 6-digit code after your password. If the code is not accepted, use one of your recovery codes — each code works once.

1.3 Status page

The Status page shows three things:

  • How many steps are complete (6 steps)
  • Institution size and supervisory authority
  • How many systems are connected (incident, service desk, compliance, inventory)

1.4 Institution details

On the Institution details page enter the institution name, size (tier), supervisory authority, country of operation and business lines. These details appear in reports and in the evidence bundle.

1.5 Setup steps

StepWhat you enter
1Your services — critical services, owners, criticality
2Outage tolerances — MTD / RTO / RPO (hours) per service
3My assets — servers/systems (CSV upload or paste) + Owners
4Scenario tests — accuracy, SLA violations, hash chain for three scenarios
5Self-assessment — coverage for 28 DORA articles and the independent reviewer
6Go-live — agent autonomy levels, shadow/semi-automatic days

Every step has a "check this step" button: anything missing is listed with a red cross.

1.6 Uploading the inventory (CSV)

  1. My assets → Download template
  2. Fill it in Excel: id, name, criticality, vendor
  3. Pick the file → it is uploaded automatically

Criticality: critical, important, standard (Turkish equivalents are also accepted).

1.7 Incident records and reporting deadlines

If a SIEM is connected, events arrive automatically; otherwise an administrator presses SIEM events → Fetch events.

  1. Find the event row in the Incident records table.
  2. Fill in customer count, outage minutes and economic impact.
  3. save → activate (with four-eyes enabled this goes to a second administrator).
  4. The Reporting deadlines card shows three counters:
StepDurationColour
Initial notification4 hoursgreen = sent, orange = approaching, red = overdue
Intermediate report72 hourssame
Final report1 monthsame
  1. After reporting outside the system, press "… sent"; you may enter a reference number.

1.8 Incident history

The history button on an incident row shows who did what and when (creation, update, reporting, approval).

1.9 Documents and evidence bundle

  • Documents lists the records produced in the session.
  • Create evidence bundle → all records in one signed zip.
  • Management report (PDF) → institution, phases, incidents, deadlines, approvals, coverage.

1.10 Search

The Search page searches processes, controls, agents, terms and DORA articles. Turkish characters are folded (siniflandirma = sınıflandırma).

1.11 Changing your password

Change my password → current password + new password (at least 8 characters). Changing it signs you out on other devices.

Part 2 — Administrator

2.2 E-mail (SMTP)

Administration → E-mail (SMTP): server, port, sender, user, password, SSL options. Verify with Send test. Undeliverable messages go to the queue; Send queue retries.

2.3 Notifications

Administration → Notifications: enable, recipients (comma-separated). When enabled, e-mails are sent for:

  • incidents whose reporting deadline is approaching or overdue
  • pending approval requests

Use Scan now to test manually. The same alert is never sent twice.

2.4 Four-eyes approval

Administration → Approval flow → Enabled. When on, incident classification and go-live go to a second administrator; the requester cannot approve their own request.

With a single administrator do not enable it — the request cannot be approved. Create a second administrator first.

2.5 Integrations

Integrations: product, endpoint, authentication and key for SIEM / ITSM / GRC / CMDB. Test connection checks reachability; the SIEM events page fetches events.

2.6 SIEM event rules and scheduled fetching

  • Event rules: which keywords open a record, plus data-loss / unauthorised-access flags.
  • Scheduled fetching: enabled + interval (minutes) → the server pulls by itself and creates

draft records.

2.7 SSO (corporate sign-in)

Administration → Corporate sign-in (SSO / OIDC): issuer, client ID, redirect URI, secret. Details: docs/SSO-KURULUM.md. It does not work without TLS.

2.9 Activity log

Administration → Activity log shows the last 150 actions; Download as CSV returns everything.

2.10 Technical panel

Technical panel in the sidebar opens the static report dashboard (processes, controls, agents, glossary, DORA mapping). Live dashboard shows live data instead.
